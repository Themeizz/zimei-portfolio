## 1. 项目概述

### 1.1 背景

需要一个对外展示个人作品与经历的网站，作为「个人名片」：让访客快速了解"我是谁、我做过什么、我能提供什么"，并方便地发起联系。同时希望这个网站是可持续维护的——即使不懂代码，也能通过可视化后台自己更新内容。

### 1.2 目标

1. **对外展示**：访客打开网站后，能快速了解子美的定位、代表作和经历，并方便地联系到子美。
2. **可编辑**：内容与代码分离，通过可视化后台（Sanity Studio）即可新增 / 修改 / 删除 / 排序作品，无需写代码。
3. **可扩展**：主题、布局、页面模块可以低成本地美化、增删和调整，方便长期演进。
4. **可发布**：部署在 Vercel，支持自定义域名、HTTPS、SEO、移动端适配。

### 1.3 非目标（当前版本明确不做）

- 不做博客板块（当前版本不做，后续如需可扩展）；
- 不做电商、支付、用户注册登录、评论区；
- 不做复杂的多用户后台管理系统；
- 不追求炫技，优先保证加载速度、维护简单和长期稳定。

## 2. 目标用户与使用场景

### 2.1 访客（读者）

- 潜在雇主 / 面试官：查看作品质量、项目细节、代码链接；
- 潜在合作方 / 客户：了解能力和案例，寻找联系方式；
- 同学、朋友、社区成员：浏览和转发。

### 2.2 维护者

- 子美本人（技术小白）：通过可视化后台独立更新内容，不需要碰代码；
- "未来的子美"（半年、一年后）：即使记忆模糊，也能快速上手修改。

### 2.3 核心使用场景

- **场景 1（访客）**：打开首页 → 3 秒内知道子美是谁、做什么 → 浏览置顶作品 → 进入作品详情 → 通过邮箱 / 社交链接发起沟通。
- **场景 2（子美）**：完成一个新作品 → 打开后台 → 填表单、传封面图 → 保存 → 网站自动更新上线。
- **场景 3（子美）**：想换整体配色或调整首页布局 → 改主题配置（换色板）或调整布局顺序，不重写代码。

## 3. 参考案例分析

### 3.1 Diogo Correia（diogotc.com）

值得借鉴的点：

- **信息架构**：首页按「Hero 简介 → 置顶作品（Top projects）→ 时间线（Timeline）」组织，信息密度高、易扫读；
- **作品呈现**：每个作品标注技术栈、链接、一句话描述，访客可以按需深挖；
- **内容与展示分离**：网站开源、静态化构建，维护成本低、加载快；
- **叙事感**：时间线把经历串成一条成长故事线，比干巴巴的作品列表更有感染力。

> 注：原站为浅色风格，我们取其信息架构，视觉风格采用暗黑科技感。

### 3.2 Craftathon（craftathon.org）

值得借鉴的点：

- **单页叙事结构**：Hero → 数据区块 → 回顾 → 团队 → 联系 CTA，逻辑清晰；
- **用数据增强说服力**：关键数字（金额、人数、时长）可视化呈现；
- **明确的 CTA**：页面始终引导访客到"联系 / 行动"。

## 6. 内容数据模型（Sanity Schema 草案）

> 设计原则：内容全部由后台管理，Schema 字段即后台表单；前台按字段渲染，内容与代码解耦。

### 6.1 站点配置 `site`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 站点 / 作者名称 |
| headline | string | 一句话简介（Hero 用） |
| bio | string | 详细介绍 |
| avatar | image | 头像 |
| email | string | 联系邮箱 |
| social | object | 社交链接（GitHub 等） |
| nav | array | 导航项 |
| footer | object | 页脚文案与链接 |
| theme | object | 主题配置（色板、字体） |

### 6.2 作品 `project`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| slug | string | 是 | 唯一标识，用于 URL |
| type | enum | 是 | 作品类型：code（编程）/ design（设计）/ writing（写作）/ other |
| title | string | 是 | 作品标题 |
| subtitle | string | 否 | 副标题 / 一句话描述 |
| summary | string | 是 | 卡片展示的简介 |
| cover | image | 是 | 封面图 |
| gallery | image[] | 否 | 详情页图集 |
| video | file / url | 否 | 视频演示（可选） |
| pdf | file | 否 | PDF / 文档（可选） |
| description | rich text | 是 | 正文（详情页展示） |
| tags / tech | string[] | 否 | 标签 / 技术栈 |
| links | object | 否 | demo、github、article 等链接 |
| date | date | 是 | 完成 / 更新时间，用于排序 |
| featured | boolean | 否 | 是否置顶精选 |
| status | enum | 否 | draft / published / hidden |
| order | number | 否 | 手动排序权重 |

> 不同类型作品在详情页差异化呈现：编程 → 强调链接与技术栈；设计 → 强调图集；写作 → 强调正文排版。

### 6.3 时间线条目 `timelineEntry`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| date | date | 时间 |
| title | string | 事件标题 |
| org | string | 组织 / 公司 / 学校 |
| type | enum | work / education / event |
| description | rich text | 详细描述 |
| links | object | 相关链接 |

### 6.4 扩展预留

博客、图库等后续板块以「新增 Schema + 新增页面」的方式扩展，不影响现有内容和数据结构。

## 8. 技术选型（已确定）

### 8.1 推荐组合

- **框架**：Next.js（App Router）；
- **CMS / 可视化后台**：Sanity（Sanity Studio）；
- **样式**：Tailwind CSS + CSS 变量（设计令牌）；
- **部署**：Vercel（连接 GitHub 仓库，push 自动部署）；
- **图片**：Sanity CDN + Next.js Image（自动压缩 / 优化）。

### 8.2 为什么这么选（说明）

1. **可视化后台体验最好**：Sanity Studio 是表单式界面，拖拽传图、可视化编辑正文，不需要懂代码；
2. **Vercel 原生支持**：Next.js 是 Vercel 出品，一键部署、自动 HTTPS、免费预览链接；
3. **免费额度足够**：Sanity 免费版 + Vercel Hobby 免费版足以支撑个人作品集；
4. **生态成熟、教程多**：Next.js + Tailwind 是最主流的组合，后续想调整样式、加功能都容易找到方案；
5. **内容可迁移**：内容与代码解耦，将来想换前台框架，Sanity 内容可以导出带走。

### 8.3 备选方案（记录备查）

- **Astro + Decap CMS**：内容直接存在 Git 仓库、无第三方托管依赖、更轻量；但后台编辑体验不如 Sanity。若后续觉得不需要复杂后台能力，可考虑切换。

## 11. 风险与开放问题

### 11.1 已确认的决策

见第 0 节「决策记录」。

### 11.2 待确认的问题

1. **自定义域名**：有没有域名？没有的话先用 `xxx.vercel.app` 免费域名，后续随时可以绑定；
2. **联系方式**：只要邮箱 + 社交链接，还是需要联系表单？
3. **作品素材**：大概有多少个作品？封面图 / 截图有没有现成的？
4. **简历页**：是否需要独立简历 URL（方便投递时直接附上）？
5. **语言**：目前只做中文，还是需要中英双语？
6. **账号准备**：开始搭建前需要 GitHub 账号（部署 + 后台登录）和 Sanity 账号（可用 GitHub / Google 登录），请确认可用。

### 11.3 风险与对策

| 风险 | 对策 |
| --- | --- |
| 可视化后台带来第三方依赖 | 使用 Sanity 免费版 + 定期导出备份，内容可迁移 |
| 图片体积拖慢性能 | Sanity CDN 自动压缩 + 懒加载 + Next.js Image |
| 技术小白后期改动困难 | README + "改内容 / 改样式"傻瓜教程；换色板即可换风格 |
| 风格与参考站雷同 | 在配色、文案、动效上做差异化 |
| 内容模型过度设计 | 先用最小字段集，有真实需求再加字段 |
